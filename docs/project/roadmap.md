- T-133 is now complete: shape fill rendering shares `renderer/appearance.ts` `drawCoveredFill` across rect, circle, and polygon while each command renderer still owns its geometry coverage. Deeper stroke/shadow/glow unification remains optional future cleanup rather than an M3 Gate B blocker.
- T-132 is now complete: `radebe-core` keeps the public `src/renderer.ts` boundary stable, but rect, circle, and polygon rendering are now split into per-command folders with `fill`, `stroke`, `glow`, and `shadow` modules plus shared raster/layer helpers.
- A 2026-05-28 maintainability audit added follow-up refactor tasks for the M3 cleanup queue: T-140 compiler modularization, T-141 shared argument binding across compiler/editor/color metadata, T-142 web Playground module split, T-143 core test-suite split, T-144 Unity bridge helper split, T-145 web CSS token/style split, T-146 web performance tooling split, and T-147 class-owned compiler/renderer architecture.
- DEC-078 sets the architecture direction for T-147 and related refactors: keep public parser/compiler/renderer function APIs as facades, keep compiled render instructions descriptive and data-oriented at package/worker/test boundaries, and move internal orchestration into classes such as compiler contexts, command compilers, document renderers, command renderers, appearance passes, samplers, layers, and masks while protecting pixel-loop performance.
- Unity/editor follow-ons such as source-authored import metadata, reusable editor packaging, the VS Code live rendered preview pane, and eventual Unity live-authoring parity are parked for M5 review. T-137 remains intentionally scoped to the VS Code extension and should not be added to the public website roadmap unless the M5 review changes that.
- M1 Gate C remains passed with the shared core/web render contract, SEA packaging pipeline, and Unity payload install/update plus smoke helper baseline in place.
- The recovered source product spec has now been realigned in code through a schema-backed `sprite` header block, root-level `plot` and `line` commands, rectangle geometry spanning `rect`, `rect-absolute`, `rect-inset`, and child `cut` plus child `radius` modifiers, the first `circle` geometry primitive, a `polygon` geometry slice using whitespace-separated `x y` point pairs or canonical child `point` nodes plus uniform per-vertex `cut` and `radius` modifiers, generated `polygon-regular` and `polygon-star` shapes with explicit `x y` centers and those same uniform polygon-corner modifiers, a first open `path` geometry slice using child `point` nodes plus required `stroke`, filled shapes with `solid`, `gradient-linear`, and `gradient-radial` appearance variants, explicit per-pass `alpha` on `fill` and `stroke`, a `shape-appearance` capability path that lets geometry commands opt into shared `fill` / `stroke` children where appropriate, circle stroke support, polygon stroke support, path stroke support, rectangle stroke contours that now follow `cut` and `radius` silhouettes, and a shared sprite-grid render artifact consumed by `radebe-core`, `radebe-cli`, `radebe-web`, and the SEA smoke path.
- The shared shape appearance-pass model now includes `shadow` for `rect`, `circle`, `polygon` including generated regular/star polygons, and composited groups, with `x`, `y`, `spread`, non-negative integer `blur`, explicit `alpha`, and either color shorthand or nested `fill`; `blur 0` preserves the original hard-edged behavior. It also includes `glow` for those same shape/group surfaces, with `mode` values `outer` and `inner`, non-negative `spread`, non-negative `blur`, explicit `alpha`, and either color shorthand or nested `fill`.
- The language now supports file-scoped variables through root `var name value` declarations and optional `vars` grouping blocks, with top-to-bottom defined-before-use resolution for whole-token references such as `$accent`.
- The language now supports `group` as an ordered structural container. Groups can be named, nested, and used to organize draw commands; groups with no group-level passes stay transparent, while groups with `fill`, `stroke`, `shadow`, or `glow` rasterize children into an offscreen layer, apply passes to the combined alpha/pixels, then composite back into the parent.
- The language now supports `mask` as an ordered structural container with `shape` and `contents` child containers. Mask shape drawables render into alpha coverage, masked contents render into an offscreen layer, `invert=true` keeps content outside the shape coverage instead of inside it, and `show=shape-only|content-only` provides mask debugging views while omitted `show` behaves as normal masked content. Full stacked mask composition modes are deferred into T-079.
- The product spec now defines author-facing language vocabulary for drawable commands, pixel primitives, shape drawables, path drawables, geometry modifiers, property commands, appearance passes, effect passes, structural containers, mask shape, and masked content. DEC-073 now also reserves `appearance passes` as the renderer-architecture umbrella for `fill`, `stroke`, `shadow`, and `glow`. Web reference docs, autocomplete details, VS Code help, and compiler diagnostics still need to adopt that vocabulary consistently.
- The accepted ordering direction is to reject confusing child ordering instead of silently moving commands across phases. Group content must now come before group-level appearance passes; follow-up compiler work should tune broader restrictions such as properties/modifiers before appearance passes on shape drawables.
- The renderer now supports optional real output antialiasing through a sprite-level `antialias` default and per-geometry overrides, defaulting to pixel-perfect `false` so existing artifacts remain stable unless authors opt in.
- T-127 now tracks a future sprite-level `outputscale` property, separate from web preview zoom, for emitting larger raster output from the same logical sprite while scaling sprite dimensions, geometry coordinates, stroke widths, corner treatments, shadows/glows, blur/spread values, and other pixel metrics together. T-131 now tracks the unresolved coordinate-space question that should be settled before or alongside `outputscale`, especially the distinction between sprite bounds/extents, pixel-cell commands, open path points, stroke centerlines, and antialiasing.
- The web example surface now treats rounded and cut corners as part of the main `rect` story instead of separate geometry pages, which keeps the current authoring model aligned with the implemented modifier-based shape semantics. T-077 now tracks the next corner-treatment refinement as a unified system across `rect` and the polygon family: targeted `cut` / `radius` selectors by index or semantic tag while still distinguishing omitted corners from explicit zero-valued treatments.
- The placeholder example audit now keeps only substantive future-feature stubs in the web nav; low-value property/container placeholders that are better covered by their parent pages have been removed.
- M2 Gate A, Gate B, and Gate C now all have working evidence. T-011 established the first real Unity plugin import baseline: `.rdb` files are Unity source assets handled by a ScriptedImporter, the packaged CLI can emit a Unity JSON sprite artifact, local deployment into a configured Unity project is driven by `.env` / environment variables rather than hard-coding Eddie into repo state, and manual verification in Eddie confirmed the deployed importer produces a generated Sprite main asset.

- Phase 5 reusable editor packaging and Phase 6 Unity live-authoring parity are intentionally postponed. They remain tracked as backlog tasks T-054 and T-055 so that reusable editor packaging or Unity IDE surface design resumes only by explicit choice.
- T-056 has added the first VS Code `.rdb` language-support package. It registers the language and TextMate grammar, consumes `@radebe/core` directly for completions, signature help, diagnostics, smart edits, and smart newline indentation, and includes a text render preview command. LSP remains a deferred architecture option if multiple editor hosts need a shared protocol boundary.
- T-057 followed user validation of the VS Code host by promoting Radebe color-token knowledge into shared `@radebe/core` metadata. VS Code now decorates named colors such as `white` through a real color provider, and the web CodeMirror editor now shows clickable color swatches with browser-picker-backed hex replacement.
- T-058 added local VS Code extension deployment automation. `npm run install:vscode` builds the workspace, stages a VSIX with the copied `@radebe/core` runtime instead of workspace symlinks, packages it with local `@vscode/vsce`, and installs it into the normal VS Code profile without Marketplace publishing.
- T-081 converted `radebe-web` from an examples-first workbench into the main user-facing site. The index route now introduces Radebe, the top bar shows `v0.1.0`, the sidebar can collapse and uses Commands sections aligned to the author vocabulary, the old experimental page is now a full-height `Try it` editor, and new Syntax, Release Notes, Roadmap, VS Code Extension, and Unity Plugin pages are available. The public roadmap page is intentionally filtered to user-facing features from the task board rather than internal fixes, and T-128 swept it to include the current planned player-facing language/tooling backlog such as output scaling, ordering diagnostics, procedural fill families, and targeted corner controls.
- T-115 reshaped the Unity bridge around a single plugin-root install layout. `Assets/Plugins/Radebe` is now the canonical target for editor scripts, bridge metadata, and the packaged CLI payload under `Tools/radebe-cli/<platform>-<arch>/`; the earlier `StreamingAssets` split is no longer the intended architecture.
- T-116 added a Unity-driven export path, but that path has now been superseded and is no longer exposed as a supported packaging command.
- T-117 proved and promoted the `.unitypackage` path without Unity. The default `npm run package:unity` command now emits the package directly from repo assets plus the packaged CLI payload, imports successfully under `Assets/Plugins/Radebe` in fresh temp Unity projects, prefers harvested Unity-authored `.meta` files checked into the repo, and matches Unity's package entry layout closely enough to import without the earlier `.meta` warnings. This gives the project a stronger zero-Unity CI direction, with synthesis reduced to fallback behavior instead of the primary metadata source.
- T-119 added the first repo-owned release pipeline baseline. For the web-only `v0.1.0` release, `azure-pipelines.yml` now builds the site on `ubuntu-latest` and publishes only the `radebe-web/dist` artifact before the Linux Cloudflare Pages deploy stage. The root `npm run build:release:web` command now delegates to the web workspace build instead of packaging the VS Code extension, SEA CLI, or Unity plugin.
- The first hosted Azure run immediately exposed an agent-tooling mismatch: Azure's Node `20.9.0` image came with npm `10.1.0`, while the repo correctly enforces npm `10.9.2`. The pipeline now upgrades npm explicitly before `npm ci`; remaining deploy readiness depends on Azure-side secret and environment setup rather than this engine mismatch.
- The pipeline YAML now explicitly links the Azure DevOps variable group `Radebe Variables` so the new repo does not depend on hidden UI-only pipeline variable wiring. The remaining hosted risk is group authorization and correctness of the values inside that library group.
- A second hosted run showed the older repo Node pin had also become stale for the VS Code packaging toolchain: `@vscode/vsce` now resolves `cheerio@1.2.0`, which requires Node `>=20.18.1`. The repo and pipeline runtime baseline have therefore been moved from `20.9.0` to `20.18.1` rather than carrying fragile transitive overrides for a build-only dependency.
- After merging to `master`, Cloudflare showed the project-update audit but no real deployment event. To reduce environment drift against the known-good legacy path, the pipeline split into a build stage and a Linux deploy stage. For the web-only release, both build and deploy use hosted Linux agents because Windows-only package artifacts are not being published.
- The next hosted run exposed the real website deploy blocker: Cloudflare Pages rejects files over `25 MiB`, and the built site was trying to ship the Windows CLI payload (`66.9 MiB`) and large Unity package inside `dist/downloads/`. The accepted `v0.1.0` mitigation is now a deliberate web-only public release: hide public integration pages, keep oversized binaries out of `dist`, and decide future artifact/source hosting separately under T-135.
- The release process is now documented separately in `docs/project/release-process.md`. Pushing to `master` still triggers CI/deploy, but a real release now explicitly requires version review, release-note updates, download/public-copy review, and post-deploy verification rather than treating deployment as the entire release ritual.
- The website version source is now intentionally split between `productVersion` and `siteVersion`, so website-only deploys can remain traceable without forcing a user-facing Radebe product version bump.
- T-082 split the web site implementation into maintainable TypeScript modules, and T-085 later superseded the no-framework direction by converting `radebe-web` to a Vite + TypeScript + Preact component app with CodeMirror retained as an editor island.
- The remaining feature backlog is now intentionally parked behind M5 review rather than treated as one long M3/M4 tail. T-059 `group` landed the transparent structural slice, T-076 extended groups with composited `fill`, `stroke`, and `shadow` passes, T-061 added soft shadow blur on the existing `shadow` command, T-062 added inner/outer `glow`, T-060 added explicit mask clipping with inversion, and T-122 added uniform polygon-family `cut` and `radius` modifiers while still deferring richer path corner semantics to T-071. T-136 continues to track possible structural repeater containers such as `repeat-linear`, `repeat-grid`, `repeat-radial`, `mirror`, `tile`, and later `repeat-along-path`, pending M5 validation.
