## Current Focus
- M1 Gate C remains passed with the shared core/web render contract, SEA packaging pipeline, and Unity payload install/update plus smoke helper baseline in place.
- The recovered source product spec has now been realigned in code through a schema-backed `sprite` header block, root-level `plot` and `line` commands, rectangle geometry spanning `rect`, `rect-absolute`, `rect-inset`, and child `cut` plus child `radius` modifiers, the first `circle` geometry primitive, a `polygon` geometry slice using whitespace-separated `x y` point pairs or canonical child `point` nodes, generated sprite-centered `polygon-regular` and `polygon-star` shapes, a first open `path` geometry slice using child `point` nodes plus required `stroke`, filled shapes with `solid`, `gradient-linear`, and `gradient-radial` appearance variants, explicit per-pass `alpha` on `fill` and `stroke`, a `shape-appearance` capability path that lets geometry commands opt into shared `fill` / `stroke` children where appropriate, circle stroke support, polygon stroke support, path stroke support, rectangle stroke contours that now follow `cut` and `radius` silhouettes, and a shared sprite-grid render artifact consumed by `radebe-core`, `radebe-cli`, `radebe-web`, and the SEA smoke path.
- The shared shape appearance/effect model now includes `shadow` for `rect`, `circle`, `polygon` including generated regular/star polygons, and composited groups, with `x`, `y`, `spread`, non-negative integer `blur`, explicit `alpha`, and either color shorthand or nested `fill`; `blur 0` preserves the original hard-edged behavior. It also includes `glow` for those same shape/group surfaces, with `mode` values `outer` and `inner`, non-negative `spread`, non-negative `blur`, explicit `alpha`, and either color shorthand or nested `fill`.
- The language now supports file-scoped variables through root `var name value` declarations and optional `vars` grouping blocks, with top-to-bottom defined-before-use resolution for whole-token references such as `$accent`.
- The language now supports `group` as an ordered structural container. Groups can be named, nested, and used to organize draw commands; groups with no group-level passes stay transparent, while groups with `fill`, `stroke`, `shadow`, or `glow` rasterize children into an offscreen layer, apply passes to the combined alpha/pixels, then composite back into the parent.
- The language now supports `mask` as an ordered structural container with `shape` and `contents` child containers. Mask shape drawables render into alpha coverage, masked contents render into an offscreen layer, `invert=true` keeps content outside the shape coverage instead of inside it, and `show=shape-only|content-only` provides mask debugging views while omitted `show` behaves as normal masked content. Full stacked mask composition modes are deferred into T-079.
- The product spec now defines author-facing language vocabulary for drawable commands, pixel primitives, shape drawables, path drawables, geometry modifiers, property commands, appearance passes, effect passes, structural containers, mask shape, and masked content. Web reference docs, autocomplete details, VS Code help, and compiler diagnostics still need to adopt that vocabulary consistently.
- The accepted ordering direction is to reject confusing child ordering instead of silently moving commands across phases. Group content must now come before group-level appearance/effect passes; follow-up compiler work should tune broader restrictions such as properties/modifiers before appearance/effects on shape drawables.
- The renderer now supports optional real output antialiasing through a sprite-level `antialias` default and per-geometry overrides, defaulting to pixel-perfect `false` so existing artifacts remain stable unless authors opt in.
- The web example surface now treats rounded and cut corners as part of the main `rect` story instead of separate geometry pages, which keeps the current authoring model aligned with the implemented modifier-based shape semantics. T-077 now tracks the next corner-treatment refinement: mixing cut and rounded corners on the same rectangle while distinguishing omitted corners from explicit zero-valued corner treatments.
- The placeholder example audit now keeps only substantive future-feature stubs in the web nav; low-value property/container placeholders that are better covered by their parent pages have been removed.
- M2 Gate A, Gate B, and Gate C now all have working evidence. T-011 established the first real Unity plugin import baseline: `.rdb` files are Unity source assets handled by a ScriptedImporter, the packaged CLI can emit a Unity JSON sprite artifact, local deployment into a configured Unity project is driven by `.env` / environment variables rather than hard-coding Eddie into repo state, and manual verification in Eddie confirmed the deployed importer produces a generated Sprite main asset.
- Unity importer-options work is closed by user request. The next Unity slice should be chosen only if Unity work is explicitly resumed.
- T-043 has been closed by user request after the importer-options code and Eddie deployment work. Reopen it only if additional hands-on Unity importer validation is explicitly requested.
- Phase 5 reusable editor packaging and Phase 6 Unity live-authoring parity are intentionally postponed. They remain tracked as backlog tasks T-054 and T-055 so that reusable editor packaging or Unity IDE surface design resumes only by explicit choice.
- T-056 has added the first VS Code `.rdb` language-support package. It registers the language and TextMate grammar, consumes `@radebe/core` directly for completions, signature help, diagnostics, smart edits, and smart newline indentation, and includes a text render preview command. LSP remains a deferred architecture option if multiple editor hosts need a shared protocol boundary.
- T-057 followed user validation of the VS Code host by promoting Radebe color-token knowledge into shared `@radebe/core` metadata. VS Code now decorates named colors such as `white` through a real color provider, and the web CodeMirror editor now shows clickable color swatches with browser-picker-backed hex replacement.
- T-058 added local VS Code extension deployment automation. `npm run install:vscode` builds the workspace, stages a VSIX with the copied `@radebe/core` runtime instead of workspace symlinks, packages it with local `@vscode/vsce`, and installs it into the normal VS Code profile without Marketplace publishing.
- T-081 converted `radebe-web` from an examples-first workbench into the main user-facing site. The index route now introduces Radebe, the top bar shows `v0.1.0`, the sidebar can collapse and uses Commands sections aligned to the author vocabulary, the old experimental page is now a full-height `Try it` editor, and new Syntax, Release Notes, Roadmap, VS Code Extension, and Unity Plugin pages are available. The public roadmap page is intentionally filtered to user-facing features from the task board rather than internal fixes.
- T-115 reshaped the Unity bridge around a single plugin-root install layout. `Assets/Plugins/Radebe` is now the canonical target for editor scripts, bridge metadata, and the packaged CLI payload under `Tools/radebe-cli/<platform>-<arch>/`; the earlier `StreamingAssets` split is no longer the intended architecture.
- T-116 added a Unity-driven export path, but that path has now been superseded and is no longer exposed as a supported packaging command.
- T-117 proved and promoted the `.unitypackage` path without Unity. The default `npm run package:unity` command now emits the package directly from repo assets plus the packaged CLI payload, imports successfully under `Assets/Plugins/Radebe` in fresh temp Unity projects, prefers harvested Unity-authored `.meta` files checked into the repo, and matches Unity's package entry layout closely enough to import without the earlier `.meta` warnings. This gives the project a stronger zero-Unity CI direction, with synthesis reduced to fallback behavior instead of the primary metadata source.
- T-082 split the web site implementation into maintainable TypeScript modules, and T-085 later superseded the no-framework direction by converting `radebe-web` to a Vite + TypeScript + Preact component app with CodeMirror retained as an editor island.
- Future language/effects backlog still includes mask composition modes, procedural fills such as noise, clouds, Voronoi, and patterns, plus follow-ons for blend modes, expressions, built-in sprite dimension variables, relative dimension units, inline comments, transforms, reusable symbols, richer paths, source-authored import metadata, boolean region operations, vocabulary/reference-doc polish, compiler ordering restrictions, and mixed per-corner rectangle treatments. T-059 `group` landed the transparent structural slice, T-076 extended groups with composited `fill`, `stroke`, and `shadow` passes, T-061 added soft shadow blur on the existing `shadow` command, T-062 added inner/outer `glow`, and T-060 added explicit mask clipping with inversion.
